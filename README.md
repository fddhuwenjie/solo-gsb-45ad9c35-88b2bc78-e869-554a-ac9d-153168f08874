# 陶瓷合窑装载确认台

用 **Python Flask + SQLite + 原生 JavaScript** 实现的合窑装载确认工具：

- **批次登记**：登记待烧批次编号及其允许的峰温闭区间（℃）、保温分钟闭区间；每次修改版本号 +1。
- **窑与窑位**：每台窑有固定编号窑位（1..N），装窑草案中一批占一位；内置 K01（8 位）、K02（6 位），可继续添加。
- **装窑草案与预览**：把批次放入窑位后，预览共同可用的峰温区间、保温区间及占位情况。
- **版本化确认**：确认必须携带预览时的草案版本与批次版本；若期间有人改了窑位占用或批次工艺范围，返回 409 提示刷新，绝不按过期预览确认。
- **确认校验（单事务，全部通过才提交）**：窑位合法且不重复、两项区间均有交集、批次未被其他已确认窑次使用；失败时指出冲突批次或窑位，草案与已确认记录均不改变，也不会占用部分批次。
- **不可变清单**：确认成功一次性保存装载清单与共同工艺区间，批次数据按当时快照存储；已确认窑次不可修改、不可删除，按快照查询，重启后仍保留（SQLite 文件持久化）。
- **并发争用**：两个草案同时争用同一批次时，确认流程串行化（全局锁 + `BEGIN IMMEDIATE` 事务），只有一个能确认成功，另一个收到 409 冲突提示。

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8000**（端口 **8000**）

数据保存在名为 `kiln-data` 的卷中（容器内 `/app/data/kiln.db`），容器重启后数据保留。

## 本地运行（不用 Docker）

```bash
pip install -r requirements.txt
python app.py
```

同样访问 http://localhost:8000 。数据库默认写入 `./data/kiln.db`，可用环境变量 `KILN_DB` 指定路径、`PORT` 指定端口。

## 使用流程

1. 在「① 批次登记」登记批次（编号、峰温上下限、保温分钟上下限）。
2. 在「② 装窑草案」选择窑，把批次放入各窑位（一批一位，同批不可重复占位）。
3. 点击「刷新预览」查看共同峰温/保温区间与占位情况（变更窑位后会自动刷新）。
4. 点击「确认装窑」：请求携带预览时的草案版本与批次版本，后端在单事务内完成全部校验并写入不可变清单；任何校验失败都整体回滚并指出冲突批次或窑位。
5. 在「③ 已确认窑次」查看按当时快照保存的装载清单。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/batches` | 批次列表（含版本号、是否已被窑次使用） |
| POST | `/api/batches` | 登记批次 |
| PUT | `/api/batches/<id>` | 修改批次（版本 +1；已被确认使用的批次禁止修改） |
| DELETE | `/api/batches/<id>` | 删除批次（已入草案或已确认的禁止删除） |
| GET | `/api/kilns` | 窑列表 |
| POST | `/api/kilns` | 添加窑（编号 + 窑位数） |
| GET | `/api/kilns/<id>/draft` | 获取（或创建）该窑的装窑草案 |
| PUT | `/api/drafts/<id>/items/<pos>` | 把批次放入窑位（草案版本 +1） |
| DELETE | `/api/drafts/<id>/items/<pos>` | 清空窑位（草案版本 +1） |
| POST | `/api/drafts/<id>/preview` | 预览：共同区间、占位、问题列表、草案/批次版本 |
| POST | `/api/drafts/<id>/confirm` | 确认装窑（携带预览版本；单事务校验并写入） |
| GET | `/api/loads` | 已确认窑次列表（不可变快照） |

### 确认请求示例

```json
POST /api/drafts/1/confirm
{
  "draft_version": 3,
  "batch_versions": {"1": 2, "2": 1}
}
```

失败返回 409 及错误码：`STALE_DRAFT`（预览后窑位被改）、`STALE_BATCH`（预览后工艺范围被改）、
`POSITION_INVALID` / `POSITION_DUPLICATE`（窑位问题）、`NO_INTERSECTION_PEAK` / `NO_INTERSECTION_SOAK`
（区间无交集，消息中指出冲突批次）、`BATCH_USED`（批次已被其他窑次使用）。

## 运行测试

```bash
pip install pytest
python -m pytest test_app.py -v
```

覆盖：区间校验、版本过期（改位置/改工艺范围）、无交集冲突定位、批次复用冲突、
两个草案并发争用同一批次仅一个成功、快照不可变、重启后数据保留。
